azk setup must coexist with hooks a project already has (husky, lefthook, hand-written), so it owns only a block between # >>> azk >>> and # <<< azk <<< markers and clear cuts exactly that back out, deleting the hook only if nothing but a shebang remains. The block goes directly after the shebang rather than at the end, because many hooks end in exit 0 and an appended block would never run; since the block always succeeds (command -v azk guard, || true) it cannot stop the rest of the hook either. A hook whose shebang is not a POSIX-ish shell is reported unsupported and left alone, since splicing sh into a node/python script would break it. The hooks dir comes from git rev-parse --git-path hooks (needs --allow-run=git) so worktrees and core.hooksPath work; post-checkout additionally checks $3 = 1 so file checkouts do not trigger a reindex.
