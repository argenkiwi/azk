setup needs a full reindex when .azk/ is missing, but calling walks/reindex.ts main() from a node would nest a state machine and print reindex's JSON summary on top of setup's, breaking the one-JSON-value-per-run contract. Instead setup wires the reindex nodes (LIST through PRUNE_ORPHANS) into its own graph and points PRUNE_ORPHANS at its own FINISH node, which folds the reindex counters into the setup summary (reporting reindex: skipped when total is unset). This keeps node files as the unit of reuse: the only cost is copying the reindex fields into setup's State and keeping the edge wiring in step with walks/reindex.ts.
