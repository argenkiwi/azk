After the monolithic-to-7-walks split, every walks/*.ts became a single-node state machine (all edges wired to null). This looks like it justifies collapsing nodes/*.ts into walks/*.ts and dropping `import defer`, but neither is done: the node/factory/edges/defaultUtils separation is what keeps nodes independently testable and reusable (the ambler-node skill's whole TDD workflow depends on it), and single-node today does not mean single-node forever. `import defer` stays for consistency with the ambler-walk skill template used across (multi-node) Ambler projects, even though a single-node walk gets no real laziness benefit from it.

What *was* genuine copy-paste boilerplate from the pre-split monolith, and got extracted:
- The `while (nodeId) { ... }` drive-to-completion loop, repeated identically in all 7 walks -> `runWalk(amble, start, state)` in a new root-level `walk.ts` (not `utils/`, since the `ambler-util` skill forbids `utils/*.ts` importing from `ambler.ts`, and `runWalk` needs the `Next` type).
- The `console.error(usage); Deno.exit(1);` guard, repeated in 5 of 7 walks -> `usageExit(message)` in new `utils/cli.ts` (plain TS, no ambler import, so utils/ is fine here).

Fixed along the way: every node's own TSDoc documents that a failed run should let the caller map its error edge to a non-zero exit, but none of the 7 walks did this (confirmed live: `azk get <missing-id>` printed the error JSON and exited 0). Since every error-carrying State has an `error?: string` field, each walk now does `if (state.error) Deno.exit(1)` after `runWalk` returns. This is a real behavior change for anything scripting `azk` and checking `$?` instead of parsing stdout.

The `ambler-walk` skill template (`.agents/skills/ambler-walk/SKILL.md`) was updated to generate this shape for future walks, so the boilerplate doesn't come back next time a walk is added. That skill file is a local vendored copy (installed via `npx skills add argenkiwi/ambler-ts`) — upstreaming this improvement is a separate, out-of-repo action.
