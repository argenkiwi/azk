Unifying azk's seven walks into one graph raised the question of how a shared node like embed can have one onEmbedded edge when create, update, search and reindex each need it to go somewhere different. The answer is to register the same factory under several node ids (CREATE_EMBED, UPDATE_EMBED, SEARCH_EMBED, REINDEX_EMBED): NodeFactory is generic over N precisely so one node can occupy many positions, and ambler memoises per id, so this costs nothing. The rule for when two verbs could instead share one id is that their chains must be identical from that node to termination — and since every verb ends at its own finish node, divergence propagates backwards and none ever are. A return-address field plus a router node was the alternative and is worse: returnTo cannot be typed (a node cannot name the walk's NodeId union), and whoever sets it needs to know node ids, which is exactly the coupling the edges parameter exists to prevent.
