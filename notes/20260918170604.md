Splitting azk's CLI into one walk per verb needed a dispatcher that loads only the verb it was given. `import defer` looks right and is the idiom used for node imports inside each walk, but it does not defer here. Verified on Deno 2.9.7: a deferred module containing top-level await does not error (contrary to what the TC39 proposal's sync-evaluation requirement suggests), but it is evaluated eagerly, before the importing file's body runs — a parent deferring two such modules prints both modules' side effects before its own first line. Every walk ends with `if (import.meta.main) await main(Deno.args)`, so naming all seven in a dispatch map would evaluate all seven on every invocation, building seven ambler node maps to run one. Dynamic `import()` is the answer, and its specifiers must stay literal: `deno install --global` statically analyses them to populate the cache, so a computed `./walks/${verb}.ts` would install a binary that fails on first use. `import defer` still pays off one level down, where each walk's node imports are synchronous and genuinely deferred.
